OS Command Injection: Variant 1 (In-Band)

Demonstration of Vulnerability Exploitation, Root Cause, and Defense Implementation

Network Diagnostic Console (Ping Utility)

Mode: Vulnerable Endpoint (/api/ping/vulnerable)

Concatenates raw user input into shell command string with shell=True. Metacharacters are interpreted and output is returned in-band.

Quick Test Payloads:
In-Band Response Console (stdout / stderr) 0 ms 
System ready. Select a mode, enter target or choose a payload above, then click Execute Ping.
Vulnerable Implementation (app.py: /api/ping/vulnerable) 
# Flaw: Concatenating unvalidated input into shell string with shell=True
raw_command = f"ping {count_flag} 1 {target}"
output = subprocess.check_output(
    raw_command,
    shell=True,  # Invokes cmd.exe / /bin/sh
    stderr=subprocess.STDOUT,
    text=True
)
Mitigated Implementation (app.py: /api/ping/mitigated) 
# Mitigation: Strict allow-list validation + Parameterized argument vector
if not is_valid_target(target):  # Rejects metacharacters, spaces, etc.
    return jsonify({"status": "blocked", "error": "Invalid target"}), 400

# shell=False ensures ping.exe is executed directly without shell interpreter
command_vector = ["ping", count_flag, "1", target]
result = subprocess.run(command_vector, shell=False, capture_output=True, text=True)

(a) Vulnerable Implementation

Located in app.py inside ping_vulnerable(). The route accepts arbitrary user input from POST body and directly formats it into a command string.

(b) Working Exploit Payload

Payload: 127.0.0.1 & whoami

The ampersand (&) acts as a command separator in cmd.exe (or ; in bash). The system executes the ping, followed immediately by whoami. Because this is Variant 1 (In-Band), the output of whoami is piped directly into stdout and returned in the HTTP response body.

(c) Root Cause

Root Cause: User-supplied input is directly concatenated into a system shell command without sanitization or validation, and executed through an operating system shell interpreter (shell=True). The shell parses metacharacters as command control syntax rather than literal data.

(d) Implemented Mitigation

Fix: Defense-in-depth using parameterized execution (passing an argument vector list with shell=False) and strict allow-list input validation (verifying target strictly matches an IPv4/IPv6 address or RFC hostname). When the exploit payload is sent, it is either blocked by validation or treated as an invalid literal host parameter, completely neutralizing execution.

Theoretical Mitigations from Lecture Slides

1. Avoid the Shell

Directly invoke binaries using system APIs (e.g., execve in POSIX, CreateProcess in Windows) rather than passing strings through sh, bash, or cmd.exe. When no shell exists, metacharacters (&, |, ;, `, $()) have no special parsing logic.

2. Parameterised Execution with an Argument Vector

Pass command arguments as separate elements of an array/vector (e.g., ["ping", "-n", "1", user_input]) with shell=False. The operating system treats the entire vector element as a single literal argument string to the executable, making command injection syntactically impossible.

3. Allow-List Input Validation

Enforce strict syntactic rules using positive allow-lists rather than blacklists. Validate inputs against strict data formats (e.g., strictly validating IPv4/IPv6 via ipaddress library, or regex ^[a-zA-Z0-9.-]+$). Any input containing illegal punctuation or spaces is rejected before processing.

4. Principle of Least Privilege

Execute the web server process under a dedicated, unprivileged service account with minimal filesystem and operating system permissions. Prevent access to dangerous binaries, administrative commands, and write access outside designated application directories, bounding the impact if an injection flaw occurs.
