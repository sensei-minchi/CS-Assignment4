Table 2(c) Root Cause: The server accepts state-changing POST requests relying solely on ambient browser credentials (session cookies) without demanding proof of user intent (an unpredictable synchronizer token). Browsers automatically attach cookies to cross-origin POST requests by default.
Table 2(e) Other Mitigations (Theory Alternatives)
  • Anti-CSRF Synchronizer Tokens (Primary Fix): Generate cryptographically random, unpredictable tokens stored in the session and verified in form payloads. Cross-origin sites cannot read this token due to the Same-Origin Policy (SOP).
  • SameSite Cookie Attribute: Setting cookies with SameSite=Strict or SameSite=Lax instructs modern browsers never to send cookies along with third-party cross-site requests.
  • Re-Authentication for Critical Actions: Prompting the user for their current password or sending an MFA confirmation code before allowing sensitive updates (e.g. email, password, financial transactions).
  • Origin & Referer Header Verification: Verifying that the HTTP Origin or Referer header strictly matches the application's trusted domain.
  • Avoid State-Changing GET Requests: Strictly adhering to HTTP semantics so that GET requests are read-only and idempotent.
